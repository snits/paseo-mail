Addresses

  • <name>: the one live agent that registered the name on the sender's daemon. Names are unique on a daemon; an agent on another daemon can hold the same name.
  • role:<role>: every live agent holding the role in the sender's workspace, else in its project, else anywhere. Each gets its own copy.
  • agent:<agent id>: that live, non-archived agent, whether or not it registered. Meant for a parent mailing a child it just created. An unknown or archived id is an error. Ids are case-sensitive.
  • <name>@<host>: the one non-archived agent that registered the name on a host this daemon is linked to in Paseo. Registering a name publishes it in the agent's Paseo metadata, which is how the other daemon finds it.
  • Names and roles are lower-case: 1–64 characters a-z, 0-9, ., _ or -.

Hosts

  • Which host: the part after the first @ is matched, in order, against this daemon (its own serverId, or its own label lower-cased and trimmed, which then resolves locally), a linked host's serverId (exact, case-sensitive), and a linked host's label, lower-cased and trimmed. A label counts only when it is a valid name and no other linked host has it; otherwise use the serverId. Disabled links are ignored. Any other host part is an error.
  • When the host is online, the name is checked at send time: nobody publishing it, or more than one agent publishing it, is an error and nothing is sent. When it is not online, or its agents cannot be listed, the send is accepted unchecked and the mail waits on the sender's daemon until the host can be reached. A typo then shows up only as mail that never leaves.
  • Shown as name@host: the tools show a party on another daemon as <name>@<host>, or agent:<agent id>@<host> when it has no name. The host is this daemon's label for it when that label reaches it, else its serverId.
  • agent:<agent id>@<host> cannot be mailed: use the agent's name.
  • role:<role>@<host> (planned): a role on another host. Today it is refused.

Tools

ToolInputWhat it does
mail_registername?, roles?Claim or change your name and roles. name: "" releases the name, roles: [] clears the roles, and no arguments shows your registration.
mail_directorynoneList registered names and roles on this daemon, and the names published on each online linked host as name@host, with the host. A host that cannot be listed is left out.
mail_sendto, subject, bodySend mail to a name, role:<role>, agent:<agent id>, <name>@<host>, or a list of them. No name is needed to send. The result tells you to use a recipient's name from now on, and warns if you have no name, since recipients cannot reply by alias. A body going to another host is at most 32 KiB (UTF-8); a larger one fails the whole send and nothing is stored.
mail_listunread_only?, limit?List your mail, newest first, without bodies. Needs a registered name; without one it refuses and gives the count of waiting mail.
mail_readidRead a mail and mark it read. Needs a registered name (a role alone does not count).
mail_replyid, bodyReply to the sender, in the same thread. A sender on another host gets the reply there; if it was archived, the reply goes to whoever holds its name on that host, and a reply to a sender that had no name cannot be delivered.

Delivery

  • Idle nudge: when an agent is idle and has unread mail it was not told about, the plugin sends it a one-line nudge. It never interrupts a running turn, and never wakes an agent again for mail it has read or was already told about.
  • Unread count: every mail tool result ends with Unread: N; for an agent with no name it adds that it cannot read until it registers.
  • Alias required to read: mail stays stored under the agent id and appears untouched once the agent registers a name. The nudge for an agent with no name says so and asks it to register, read, and reply so the sender learns its alias.
  • Durable: mail is stored in $PASEO_HOME/plugin-data/lerenn/mail/ and survives restarts.
  • Mail rule: new agents get a short rule in their system prompt: use mail for all non-urgent communication with other agents, and interrupt with a direct prompt only when it is urgent. It is enforced only by the prompt, and agents created before the plugin was installed do not get it.
  • Bounces: when an agent is archived, its unread mail from senders on the same daemon goes back to them as Returned: <subject>. Unread mail from a sender on another host stays where it is.
  • Across hosts: mail to name@host is stored on the sender's daemon first, then handed to the other daemon when that host is online: after the send, when the host comes back, and on a sweep every minute. Mail from one daemon to a host is handed over in the order it was sent. At hand-off an archived or missing recipient is looked up again by its name on that host. The receiving daemon checks that the sender exists on a linked host, stores the mail, and nudges the recipient as usual. Both directions of the link must work: if the receiving daemon cannot reach the sender's, the mail waits there until it can.
  • Not yet across hosts:
    • The archive bounce across hosts (planned): unread mail from a sender on another host going back to it when the recipient is archived.
    • The 24h outbox bounce (planned): mail that could not be handed off within 24 hours going back to its sender. Today it keeps waiting.
    • The bounce for unresolvable addresses (planned): mail whose name no agent on the host publishes once it is reachable going back to its sender. Today it stays on the sender's daemon and the plugin logs it.

Mail screen

  • Open it from the Mail row in Paseo's sidebar.
  • Mailboxes: every agent with a registration or mail. The number is the mail its agent has not read. Archived agents are listed under Archived, with how much of their mail was returned.
  • Mail list: newest first. Bold means no human has opened it; unread means its agent has not read it; returned means it bounced.
  • Reader: the whole thread, oldest first, with when each mail was read by its agent or the agent was told about it. Mark as not opened makes a mail bold again; Open agent opens the recipient's chat.
  • View only: a human cannot send, reply or mark mail read for an agent.
  • Hosts on the Mail screen (planned): the screen does not show hosts yet, so a sender on another host appears without its host.
